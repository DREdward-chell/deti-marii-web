# Пространство волонтёров Дети Марии

Монорепозиторий прототипа для сопровождения волонтёров: знакомство, подготовка, подбор возможностей, участие и подтверждение вклада. Бэкенд — модульный монолит Spring Boot + Kotlin; фронтенд — React + TypeScript.

Готовы архитектурная основа, регистрация и собственная анкета волонтёра, кабинет координатора с поиском, просмотром карточек и рассмотрением обращения. Координатор сохраняет сообщение и следующий шаг для волонтёра, отдельную внутреннюю заметку и историю изменений. Для сотрудников обязателен вход с паролем и кодом из письма. Аккаунт отделён от профиля; владелец определяется по серверной сессии. Обучение (`learning`) отделено от вступления и допусков (`onboarding`); подключено постоянное хранение публикаций межмодульных событий. Добавлены ручное подтверждение оформления, независимые допуски к видам помощи и редактируемый справочник направлений. Готово обучение: редактор текстовых уроков и интерактивных заданий, публикация версий, сохранённый прогресс и доступ после подтверждения оформления. Добавлен каталог возможностей помощи: отдельные черновики и публикации координатора, поиск и фильтры для оформленных волонтёров. Материалы фонда, занятия, отклики и Telegram-бот подключаются отдельными этапами.

## Запуск целиком

Нужны Docker Engine с Compose v2 или Docker Desktop. Команды выполняются из корня репозитория.

```sh
cp .env.example .env
docker compose up --build -d --wait
```

Открыть <http://localhost:8088>. Caddy отдаёт интерфейс и направляет `/api/*` в бэкенд.

Переключитесь на «Регистрация», укажите email и пароль от 15 символов и нажмите «Создать аккаунт», затем заполните анкету. Предустановленных учётных записей нет: регистрация выдаёт только роль волонтёра. Имя, контакты, интересы, навыки и доступное время — начальный состав полей; он будет уточнён по материалам фонда.

Анкета сохраняется в PostgreSQL. Сессия действует 30 минут бездействия и хранится в памяти backend: после его перезапуска нужно войти снова. Подтверждение email при регистрации волонтёра и восстановление пароля пока не реализованы.

## Кабинет координатора и локальная почта

Для проверки без рабочего почтового ящика запустите локальную SMTP-песочницу:

```sh
docker compose -f compose.yaml -f compose.mailpit.yaml up --build -d --wait
```

Приложение остаётся на <http://localhost:8088>, письма доступны в Mailpit на <http://localhost:8025>. Они не отправляются внешним адресатам. Этот дополнительный Compose-файл предназначен только для локальной разработки; порты почты привязаны к loopback.

Создайте обычный аккаунт через интерфейс. Оператор развёртывания может назначить ему роль координатора:

```sh
bash scripts/coordinator-access.sh grant coordinator@example.org 'Имя оператора'
```

Выйдите и войдите снова: после пароля потребуется шестизначный код из письма. При отзыве роли существующие сессии перестают работать со следующего запроса:

```sh
bash scripts/coordinator-access.sh revoke coordinator@example.org 'Имя оператора'
```

Скрипт требует доступ к БД развёртывания, не создаёт аккаунт и записывает действие в аудит. Публичная регистрация никогда не выдаёт права сотрудника. Координаторский кабинет позволяет читать анкеты, фиксировать рассмотрение, оформление и допуски, а также управлять учебными маршрутами. Подробности настройки рабочего SMTP — в [руководстве разработки](docs/development.md).

Проверка готовности: <http://localhost:8088/actuator/health/readiness>.

```sh
docker compose logs -f backend web
docker compose down
```

Остановка сохраняет данные PostgreSQL. Не добавляйте `--volumes` / `-v`, если данные нужны.

## Проверка обучения

Координатор: откройте «Учебные маршруты» → «Создать маршрут». Можно добавить собственные уроки или нажать «Заполнить демопример», затем «Сохранить черновик» и «Опубликовать маршрут». Демопример посвящён работе с кабинетом и явно помечен; он не содержит утверждённых правил фонда. Начальная база не содержит курсов.

Волонтёр с сохранённой анкетой: откройте «Моё обучение», начните маршрут, прочитайте материал, ответьте на вопрос и восстановите порядок действий. Ошибку можно исправить. После возвращения сохранённые ответы и прогресс восстановятся. В карточке волонтёра координатор может нажать «Показать прогресс обучения».

У аудитории «После подтверждения оформления» доступ проверяется при каждом чтении и ответе. Новая публикация не перезаписывает начатую версию. Снятие маршрута с публикации закрывает его для волонтёров и сохраняет историю для координатора.

## Проверка каталога возможностей

В кабинете координатора откройте «Возможности помощи», создайте карточку и выберите вид помощи из справочника. Заполните описание, место и ритм участия, сохраните черновик и опубликуйте. Пока правки находятся в черновике, волонтёры продолжают видеть предыдущую публикацию. Снятие с публикации скрывает карточку, история сохраняется.

Волонтёр с подтверждённым оформлением открывает «Найти дело»: доступны поиск, фильтры по виду помощи и регулярности, подробные условия и собственный статус допуска. Если оформление ещё не подтверждено, каталог закрыт. На этом этапе просмотр не создаёт отклик: конкретные занятия и запись добавляются отдельно. Для проверки используйте явно помеченный демопример; реальные вакансии фонда не добавляются автоматически.

## Локальная разработка

Нужны JDK 25, Node.js 22.23.1, npm 10+ и работающий Docker. Gradle устанавливать отдельно не нужно: используется Wrapper с проверкой контрольной суммы.

```sh
make init
make db
```

Затем в двух терминалах:

```sh
make api
```

```sh
make web
```

Интерфейс: <http://localhost:5173>. Бэкенд: <http://localhost:8081>. Vite проксирует `/api` в бэкенд. `make api` загружает переменные из `.env`; при запуске из IDE задайте их в конфигурации запуска. Если меняете порт бэкенда, передайте `API_PROXY_TARGET=http://127.0.0.1:НОВЫЙ_ПОРТ` процессу Vite.

Если Java не находится, укажите `JAVA_HOME` на JDK 25. PostgreSQL для локальной разработки публикуется только на `127.0.0.1:5432`; порт можно изменить в `.env`.

## Проверки

```sh
npm run check
cd backend
./gradlew check bootJar
```

Или `make check` из корня. Для интеграционных тестов бэкенда нужен Docker: Testcontainers создаёт отдельную PostgreSQL и не использует вашу рабочую базу.

Фронтенд проверяется форматированием, линтером, TypeScript, Vitest и production-сборкой. Бэкенд проверяет границы модулей, миграции, транзакционность событий, регистрацию и сессии, CSRF, принадлежность профиля, конкурентное сохранение, вход по коду, отзыв прав и координаторский доступ, версии обучения, порядок шагов, проверку ответов и ограничения аудитории. Те же проверки настроены в GitHub Actions.

## Публичное развёртывание

В `.env` укажите домен в `SITE_ADDRESS`, `HTTP_PORT=80`, `HTTPS_PORT=443`, `SESSION_COOKIE_SECURE=true` и собственный пароль БД. Домен должен указывать на сервер; Caddy сможет получить сертификат при доступных портах 80 и 443. База и JVM не публикуют порты в полном Compose-стеке.

Изменение `POSTGRES_PASSWORD` в `.env` не меняет пароль в уже созданной БД: его нужно обновить в PostgreSQL отдельно. Для реального пилота также потребуются управление учётными записями и восстановление доступа, согласованные права сотрудников и резервное копирование.
