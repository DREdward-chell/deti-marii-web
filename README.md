# Пространство волонтёров Дети Марии

Монорепозиторий прототипа для сопровождения волонтёров: знакомство, подготовка, подбор возможностей, участие и подтверждение вклада. Бэкенд — модульный монолит Spring Boot + Kotlin; фронтенд — React + TypeScript.

Готовы архитектурная основа и первый пользовательский сценарий: регистрация по email, вход, выход и сохранение собственной анкеты волонтёра. Аккаунт отделён от профиля; владелец определяется по серверной сессии. Обучение (`learning`) отделено от вступления и допусков (`onboarding`); подключено постоянное хранение публикаций межмодульных событий. Кабинет координатора, 2FA, обучение и Telegram-бот — следующие этапы.

## Запуск целиком

Нужны Docker Engine с Compose v2 или Docker Desktop. Команды выполняются из корня репозитория.

```sh
cp .env.example .env
docker compose up --build -d --wait
```

Открыть <http://localhost:8088>. Caddy отдаёт интерфейс и направляет `/api/*` в бэкенд.

Переключитесь на «Регистрация», укажите email и пароль от 8 символов и нажмите «Создать аккаунт», затем заполните анкету. Предустановленных учётных записей нет: регистрация выдаёт только роль волонтёра. Имя, контакты, интересы, навыки и доступное время — начальный состав полей; он будет уточнён по материалам фонда.

Анкета сохраняется в PostgreSQL. Сессия действует 30 минут бездействия и хранится в памяти backend: после его перезапуска нужно войти снова. Подтверждение email и восстановление пароля пока не реализованы.

Проверка готовности: <http://localhost:8088/actuator/health/readiness>.

```sh
docker compose logs -f backend web
docker compose down
```

Остановка сохраняет данные PostgreSQL. Не добавляйте `--volumes` / `-v`, если данные нужны.

## Локальная разработка

Нужны JDK 25, Node.js 22.23.1, npm 10+ и работающий Docker. Gradle устанавливать отдельно не нужно: используется Wrapper с проверкой контрольной суммы.

```sh
make init
make db
```

Затем в двух терминалах:

```sh
make api
```

```sh
make web
```

Интерфейс: <http://localhost:5173>. Бэкенд: <http://localhost:8081>. Vite проксирует `/api` в бэкенд. `make api` загружает переменные из `.env`; при запуске из IDE задайте их в конфигурации запуска. Если меняете порт бэкенда, передайте `API_PROXY_TARGET=http://127.0.0.1:НОВЫЙ_ПОРТ` процессу Vite.

Если Java не находится, укажите `JAVA_HOME` на JDK 25. PostgreSQL для локальной разработки публикуется только на `127.0.0.1:5432`; порт можно изменить в `.env`.

## Проверки

```sh
npm run check
cd backend
./gradlew check bootJar
```

Или `make check` из корня. Для интеграционных тестов бэкенда нужен Docker: Testcontainers создаёт отдельную PostgreSQL и не использует вашу рабочую базу.

Фронтенд проверяется форматированием, линтером, TypeScript, Vitest и production-сборкой. Бэкенд проверяет границы модулей, миграции на чистой PostgreSQL и обновление базы с `V1`, транзакционность событий, регистрацию и сессии, CSRF, принадлежность профиля и конкурентное сохранение. Те же проверки настроены в GitHub Actions.

## Публичное развёртывание

В `.env` укажите домен в `SITE_ADDRESS`, `HTTP_PORT=80`, `HTTPS_PORT=443`, `SESSION_COOKIE_SECURE=true` и собственный пароль БД. Домен должен указывать на сервер; Caddy сможет получить сертификат при доступных портах 80 и 443. База и JVM не публикуют порты в полном Compose-стеке.

Изменение `POSTGRES_PASSWORD` в `.env` не меняет пароль в уже созданной БД: его нужно обновить в PostgreSQL отдельно. Для реального пилота также потребуются управление учётными записями и восстановление доступа, согласованные права сотрудников и резервное копирование.
