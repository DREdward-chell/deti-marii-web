## Что изучено и реализовано

На момент разработки в main есть Kotlin/Spring Boot, PostgreSQL, сессионная авторизация, CSRF, собственная анкета и границы предметных модулей. У `opportunities` и `participation` пока только пакеты: REST API событий, допуски, отклики и подтверждения не реализованы. Документация архитектуры описывает целевую модель, а не готовый API.

Из веток `design/brand-tokens`, `design/questionnaire`, `feature/profile-form` взята общая визуальная основа: Inter Variable, оригинальный SVG из проекта, тёплый фон, оранжевая основная кнопка, тематические подложки, светлая и тёмная темы. Общие компоненты и анкета не переписывались.

Продуктовая основа — локальные материалы `deti-marii-volunteers`, в частности документы 04, 05, 09, 12, 13, 14, 16, 17. Отклик не равен подтверждению, подтверждение не означает явку, пройденный курс не открывает допуск. Каталог доступен после решения координатора. Цвет означает направление, текст — статус. Резерв, автоматическая бронь, создание событий волонтёром и перенос событий перетаскиванием не вводятся.

### Просмотр

- Неделя и день с сеткой всех 24 часов; месяц с 42 ячейками; список следующих 30 дней.
- На телефоне по умолчанию список, остальные виды доступны. Широкие сетки имеют собственную горизонтальную прокрутку, страница помещается в экран.
- Москва, `Europe/Moscow`, UTC+3 независимо от часового пояса устройства. Неделя начинается с понедельника.
- «Сегодня», предыдущий/следующий период, мини-календарь и прямой ввод даты.
- Дата, вид и открытое событие хранятся в URL. Назад/вперёд восстанавливают состояние. Поиск и фильтры действуют до перезагрузки.
- При открытии временной сетки, смене периода или изменении времени самого раннего отфильтрованного события — прокрутка к нему с отступом 30 минут. Без событий — 07:30. Изменение только статуса участия не сбрасывает прокрутку.
- Пересекающиеся события располагаются в отдельных колонках. Ночные события делятся по границам дней; `endsAt` исключается из интервала. События на весь день расположены отдельно.
- Поиск по названию, месту и роли; направления; все события / мои участия / доступные для отклика / ожидающие решения. Фильтры пересекаются.
- Пустой список, загрузка, ошибка с повтором, закрытый доступ, недоступная ссылка на событие.

### Участие

Карточка содержит время, место, описание, роль, подготовку, координатора, свободные места и статус. Отклик требует подтверждения намерения и становится `pending` только после успешного ответа. Повторная отправка блокируется на время запроса. Отзыв также требует подтверждения, после успеха становится `withdrawn`. На ошибке исходное состояние сохраняется; `409` требует обновления условий.

Нельзя откликнуться на отменённое, начавшееся, закрытое, заполненное или требующее дополнительного допуска событие. Для уже ожидающих/подтверждённых откликов доступен отзыв до начала. Отказ координатора не снимается новой кнопкой записи. При пересечении с подтверждённым участием предупреждение учитывает даже скрытые фильтрами мероприятия. Это предупреждение, а не установленный фондом запрет.

Диалог использует нативный `showModal`: фокус внутри, Escape и кнопка закрытия, возврат фокуса, отдельный шаг подтверждения. Во время отправки закрытие блокируется. Сервер по-прежнему обязан проверять все условия.

Экспорт `.ics`: одно событие либо будущие подтверждённые участия, стабильный UID, версия, UTC, экранирование и перенос длинных UTF-8 строк. Это скачиваемый снимок, не подписка и не автоматическая синхронизация Google Calendar. Telegram-уведомления не имитируются.

## Запуск и режимы

```sh
npm ci
npm run dev
# http://127.0.0.1:5173/calendar?demo=1
```

Демо открывается без авторизации, содержит только вымышленные события относительно текущей недели и явно подписано. Все отклики находятся в памяти вкладки и сбрасываются после перезагрузки; сервер не вызывается. Обновление данных в интерфейсе сохраняет демо-отклики текущей сессии вкладки.

Обычный `/calendar` проходит существующую авторизацию. До реализации сервера он показывает «Готовим расписание» и ссылку на пример. Нет автоматической подмены сетевых ошибок демонстрационными данными.

Для реального API после реализации контракта установите `VITE_CALENDAR_API_ENABLED=true` в окружении Vite **при сборке**. Не включайте флаг до появления серверных маршрутов и проверок доступа. Vite работает из `frontend/`: локальный файл — `frontend/.env.local`; для production флаг теперь передаётся из корневого `.env` через Compose build args в Dockerfile; после изменения нужна пересборка `web`.

## Предложенный контракт, пока не реализованный сервером

Адаптер: `frontend/src/features/calendar/repository.ts`. Он использует существующий `shared/api/client.ts`: cookie текущей сессии, новый CSRF-токен на изменение, ProblemDetail. Не принимает accountId из браузера.

### GET `/api/v1/calendar`

```json
{
  "access": "granted",
  "events": [
    {
      "id": "event-uuid",
      "title": "Творческая мастерская",
      "description": "Помогаем ведущему подготовить материалы и провести занятие.",
      "startsAt": "2026-10-22T11:00:00+03:00",
      "endsAt": "2026-10-22T13:00:00+03:00",
      "allDay": false,
      "direction": "creative",
      "location": "Мастерская фонда",
      "role": "Помощник ведущего",
      "requirements": "Нужен допуск к направлению",
      "coordinator": "Координатор фонда",
      "status": "scheduled",
      "participation": "none",
      "registration": "open",
      "availablePlaces": 3,
      "version": 0
    }
  ]
}
```

- Закрытый каталог: `{"access":"restricted","events":[]}` без данных мероприятий. UI дополнительно отбрасывает события из такого ответа.
- `startsAt`, `endsAt`: ISO 8601 с Z/offset, конец строго позже начала. Для `allDay` обе границы — московская полночь; конец исключительный.
- `direction`: `creative | community | learning | help`.
- `status`: `scheduled | cancelled`.
- `participation`: `none | pending | confirmed | withdrawn | declined` — только участие текущего аккаунта.
- `registration`: `open | full | closed | restricted`; при ограничении — необязательный `restrictionReason`.
- `availablePlaces`: неотрицательное целое либо `null`, если лимит не применяется. Отклик `pending` не объявляется бронью.
- `version`: неотрицательное целое, меняется при изменении существенных условий или текущего отклика.

Для текущего объёма адаптер загружает весь доступный каталог одним ответом. Фильтры работают локально. Для большого каталога потребуется диапазон с учётом пересечения интервалов, пагинация и отдельная загрузка всех собственных участий для проверки конфликтов. Не добавлять скрытую серверную пагинацию без изменения клиента.

### PUT `/api/v1/calendar/events/{eventId}/response`

```json
{ "action": "apply", "version": 0 }
```

`action`: `apply | withdraw`. Успех `200`: актуальный полный объект мероприятия с собственным статусом и новой версией. Сервер проверяет аккаунт, допуск, срок, статус, вместимость и версию в транзакции. Уникальность отклика на аккаунт/событие, повтор одного действия идемпотентен. Подтверждение координатора — отдельный серверный сценарий, недоступный этим запросом.

`401`: повторный вход; `403`: доступ/CSRF; `409`: изменились условия, лимит или версия, обязательная перезагрузка; остальные ошибки: без изменения статуса, повтор доступен. Возможность отмены после начала пока закрыта в интерфейсе и требует решения фонда. Резерв, дедлайны, повторное согласие после переноса и часы участия — отдельные согласуемые расширения.

Маршруты должны быть разрешены в Spring Security с проверкой владельца и допуска; существующий `anyRequest().denyAll()` менять широко нельзя. Владельцы предметной логики остаются `opportunities` и `participation`, детали реализации согласуются с автором бэкенда.

## Проверки

`npm run check`: формат, oxlint, TypeScript, Vitest, production build. Тесты календаря проверяют границы дат/часового пояса, високосный год, пересечения/ночные события, ограничения записи и отмены, ICS, реальную последовательность подтверждения и ответа, двойной клик, ошибку сети, конфликт версии, фильтры, доступ, URL-навигацию, CSRF и автоматическую прокрутку к существующим событиям.
