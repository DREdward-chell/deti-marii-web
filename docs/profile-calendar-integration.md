# Компактный профиль и календарь: передача команде

Ветка `feat/compact-profile-calendar`, основание — `design/account-page@c284703`.
Обновлённая карточка дня `TodayCard` сохранена: дата, таймлайн, отметка текущего времени и переход на выбранный день большого календаря. Её визуальные стили не менялись.

## Профиль

Справа от фото — компактная сетка общих сведений и редактирование на месте. Длинные ответы раскрываются кнопкой, полная анкета доступна отдельно. Под сведениями находится точка подключения обучения; следующий шаг и сворачиваемые документы/допуски идут ниже. На телефоне: фото → сведения/обучение → календарь → следующие шаги. Используются существующие Inter, цвета, темы, кнопки и скругления проекта.

## Подключение работы коллеги по обучению

`AccountPage` принимает необязательный `learning: AccountLearning` из `AccountLearningCard.tsx`.
Это контракт представления, **не новый серверный API**. В `App.tsx` он пока не передаётся: backend принятия и учебный экран ещё разрабатываются отдельно.

После получения реального разрешения сервера и опубликованного маршрута передать:

```tsx
<AccountPage
  account={account}
  onOpenQuestionnaire={openQuestionnaire}
  onSessionExpired={expired}
  learning={{
    access: 'granted',
    title: course.title,
    completedLessons: course.completedLessons,
    totalLessons: course.totalLessons,
    nextLesson: course.nextLessonTitle,
    href: '/learning', // пример: заменить на фактический маршрут коллеги
  }}
/>
```

- `undefined` (ещё загружается/не подключено/ошибка) или `{ access: 'restricted' }` — раздел не рисуется, пустого места нет.
- `granted` должен происходить из актуального разрешения сервера **после принятия админом**. Нельзя выводить его из роли `VOLUNTEER`, `CONTINUE`, подтверждения документов или одного допуска.
- После отзыва принятия передать `restricted`. Загрузка содержания и ответы проверяются сервером независимо от видимости блока.
- Карточка показывает прогресс, «Начать», «Продолжить» или возврат к пройденным материалам. Без опубликованных уроков нет ссылки на несуществующее прохождение.
- Коллега подключает реальный маршрут учебного экрана и возврат в профиль. В этой ветке самого экрана, вымышленного endpoint и фиктивного принятия нет.

## Календарь

Большой календарь уже был включён коллегой в `c284703`. Виджет и страница используют один API-адаптер и общую настройку включения. Ссылка виджета открывает `/calendar?date=YYYY-MM-DD&view=day`; демо дополнительно получает `demo=1`. Возврат в профиль — существующая ссылка `/`.

Серверные endpoints по-прежнему требуется реализовать по [контракту календаря](calendar.md):

- `GET /api/v1/calendar` — события и актуальный доступ;
- `PUT /api/v1/calendar/events/{eventId}/response` — отклик/отмена с версией и CSRF.

При возвращении во вкладку или восстановлении страницы из browser cache клиент перечитывает события и права. Виджет также перечитывает данные при смене московской даты. Ограниченный ответ не показывает каталог, даже если сервер ошибочно вложил события. Сетевая ошибка не переключает реальный режим в демонстрационный.

До готовности сервера сохраняется поведение коллеги: виджет показывает явно помеченный пример, большой `/calendar` — состояние подготовки, а `?demo=1` — вымышленные события. Демо-отклики не отправляются в фонд и живут только до перезагрузки. Реальные отклики должны храниться сервером; localStorage для них не добавлялся.

### Включение реального API

1. Развернуть серверные маршруты и проверки доступа.
2. Локально установить `VITE_CALENDAR_API_ENABLED=true` в `frontend/.env.local` и перезапустить Vite.
3. Для Compose установить флаг в корневом `.env` и пересобрать `web`: `docker compose up -d --build web`.

Ветка добавляет передачу флага через Compose build args и Dockerfile. Это настройка **сборки**, смена только runtime-переменной контейнера не меняет готовый JavaScript. Значение по умолчанию — `false`.

## Проверки

Существующие тесты сохранены. Добавлены проверки скрытия/отзыва учебного блока и полного клиентского пути с имитацией HTTP-ответов на уровне fetch: карточка дня → календарь → CSRF и отправка отклика → повторное чтение в виджете. Это не проверка отсутствующего реального backend.

Визуальная проверка выполнена на вымышленных данных при ширинах 1280 и 390 px, в светлой/тёмной теме. Учебная карточка проверялась через временную локальную страницу, которая не входит в коммит. Автоматические проверки: Vitest, TypeScript, oxlint, Prettier, production build. Реальный backend и Docker-сборка не запускались: Docker daemon недоступен.

## Слияние

Ветка основана на обновлённом профиле, а не на старом календаре. `App.tsx`, файлы учебного экрана и серверный код в этой работе не изменялись. Коллеге по обучению нужно подключить один prop в месте сборки профиля. Не вливать старый `feat/events-calendar` поверх нового `App.tsx` с заменой авторизации.
