# API: аккаунт, анкета и кабинет координатора

Базовый путь — `/api/v1`. JSON-запросы и ответы. Браузер обращается к тому же origin через Caddy или Vite, аутентификация — cookie `JSESSIONID`.

## Запросы

| Метод | Путь                                   | Доступ                       | Результат                                                            |
| ----- | -------------------------------------- | ---------------------------- | -------------------------------------------------------------------- |
| GET   | `/auth/csrf`                           | Все                          | `200`, `{headerName, token}`                                         |
| GET   | `/auth/session`                        | Все                          | `200`, `{account, verification}`; оба поля могут быть `null`         |
| POST  | `/auth/register`                       | Все, CSRF                    | `201`, `{id, email, roles}`                                          |
| POST  | `/auth/login`                          | Все, CSRF                    | `200`, аккаунт волонтёра; `202`, ожидание кода сотрудника            |
| POST  | `/auth/email-code/verify`              | Незавершённый вход, CSRF     | `200`, аккаунт и аутентифицированная сессия                          |
| POST  | `/auth/email-code/resend`              | Незавершённый вход, CSRF     | `200`, новый срок и задержка повторной отправки                      |
| POST  | `/auth/logout`                         | CSRF                         | `204`, сессия уничтожена                                             |
| GET   | `/volunteers/me`                       | Волонтёр                     | `200`, профиль; `404`, если ещё не создан                            |
| PUT   | `/volunteers/me`                       | Волонтёр, CSRF               | `200`, созданный или обновлённый профиль                             |
| GET   | `/coordination/volunteers`             | Координатор после кода       | `200`, страница списка                                               |
| GET   | `/coordination/volunteers/{id}`        | Координатор после кода       | `200`, карточка; `404`, если её нет                                  |
| GET   | `/coordination/volunteers/{id}/review` | Координатор после кода       | `200`, рассмотрение и последние 50 ревизий; `404`, если нет анкеты   |
| PUT   | `/coordination/volunteers/{id}/review` | Координатор после кода, CSRF | `200`, сохранённое рассмотрение; `409`, конфликт версии              |
| GET   | `/onboarding/me`                       | Волонтёр                     | `200`, собственный результат и следующий шаг; `404`, если нет анкеты |

## Регистрация и вход

Тело обеих операций:

```json
{ "email": "volunteer@example.org", "password": "example long passphrase" }
```

Регистрация требует корректного email до 254 символов и пароля от 15 до 128 символов. Email хранится в нижнем регистре без крайних пробелов; пароль не преобразуется. Повторный email даёт `409`. Передаваемые клиентом роли не применяются: создаётся только `VOLUNTEER`. Регистрация не выполняет вход; интерфейс после успешной регистрации отдельно вызывает login.

Для любого POST/PUT сначала выполните `GET /auth/csrf`, сохранив cookie, затем передайте значение `token` в заголовке с именем `headerName`. После входа меняются идентификатор сессии и CSRF-токен; перед следующим изменением нужен новый токен. Выход также требует CSRF. Cookie имеет `HttpOnly`, токен входа в JavaScript не возвращается.

Неверный пароль и неизвестный аккаунт возвращают одинаковый `401`. Регистрация, вход, проверка и повторная отправка кода ограничены общим лимитом 30 запросов в минуту с одного IP; превышение возвращает `429` и `Retry-After` в секундах.

## Дополнительный шаг входа сотрудников

После правильного пароля аккаунт с ролью `COORDINATOR` или `ADMIN` получает `202`:

```json
{
  "verificationRequired": true,
  "expiresAt": "2026-10-21T12:05:00Z",
  "resendAfterSeconds": 60
}
```

Аутентификации ещё нет: `GET /auth/session` возвращает `account: null` и объект `verification` с этими полями. Клиент может восстановить этот экран после обновления страницы. Код в API не возвращается.

`POST /auth/email-code/verify` принимает `{"code":"123456"}` со свежим CSRF и cookie того же браузера. Код — шесть цифр, действует пять минут, максимум пять попыток. Успешная проверка создаёт полную сессию и возвращает аккаунт как обычный login. Неверный, исчерпанный, просроченный или использованный код — `401`; незавершённая проверка не открывает ни один бизнес-маршрут.

`POST /auth/email-code/resend` без тела заменяет код в текущей незавершённой проверке. Повтор возможен раз в минуту на аккаунт, включая входы из других браузеров. После истечения срока или пяти ошибок нужно начать с пароля заново. Ошибка SMTP даёт `503`, без аутентификации и без нового действующего кода. Для отмены используйте обычный logout.

Изменение ролей или `security_version` отзывает полную сессию на следующем запросе (`401`) и не позволяет завершить старую проверку кода. Роль в API не заменяет серверную проверку доступа.

## Анкета

Первое сохранение:

```json
{
  "displayName": "Анна",
  "phone": "",
  "interests": "Творческие занятия",
  "skills": "Рисование",
  "availability": "По субботам",
  "regularity": "REGULAR",
  "version": null
}
```

Имя обязательно (до 100 символов), остальные текстовые поля необязательны: телефон до 40, интересы и навыки до 1000, доступность до 500. `regularity` принимает `UNSURE`, `ONE_OFF` или `REGULAR`. Текстовые поля обрезаются по краям. Это начальные поля прототипа, а не утверждённая анкета фонда.

Ответ содержит эти поля, `id`, целочисленную `version` (начиная с `0`) и `updatedAt` в ISO 8601. При редактировании отправляйте полный набор полей и последнюю полученную версию. Пропущенные необязательные поля получают значения по умолчанию; это не PATCH.

Владелец определяется только по серверной сессии. Ни `accountId`, ни `id` из тела не меняют владельца. Волонтёру недоступны список анкет и чтение чужой карточки.

Повтор запроса с теми же нормализованными значениями возвращает текущую анкету без новой версии. При другой версии и отличающихся значениях возвращается `409`: загрузите актуальную анкету и дайте человеку решить, какие данные сохранить. Интерфейс не затирает несохранённые правки автоматически.

## Кабинет координатора

`GET /coordination/volunteers` принимает `q` (подстрока имени без учёта регистра, максимум 120 символов), `regularity` (необязательно), `page` (от 0 до 100000) и `size` (1–100, по умолчанию 20). Символы `%` и `_` в `q` считаются обычными символами, а не SQL-шаблонами. Сортировка: время создания анкеты по убыванию, затем ID. Ответ: `{items, total, page, size}`. В `items` — `id`, `displayName`, `regularity`, `availability`, `createdAt`; без контактных данных и аккаунтов, ещё не сохранивших анкету.

`GET /coordination/volunteers/{id}` дополнительно возвращает `email`, `phone`, `interests`, `skills`, `updatedAt`. ID — идентификатор анкеты. Учётные данные и `accountId` не возвращаются. Оба маршрута доступны только координатору, завершившему вход по коду. Изменения чужих анкет этим API не поддерживаются.

## Рассмотрение и следующий шаг

`GET /coordination/volunteers/{id}/review` возвращает `{current, history}`. `current` содержит `fields`, `version`, `updatedAt`, `actorId`, `actorEmail`; `history` — последние 50 таких снимков, от новых к старым. Автор определяется сервером; email — текущее значение аккаунта автора. Для ещё не рассмотренной анкеты: версия `0`, статус `NEW`, пустые тексты, `null` у даты, ответственного, автора и времени, пустая история. Чтение не создаёт запись в БД.

`PUT /coordination/volunteers/{id}/review` принимает полное состояние:

```json
{
  "version": 0,
  "fields": {
    "status": "CONTINUE",
    "message": "Рады познакомиться! Свяжемся с вами, чтобы выбрать время звонка.",
    "nextStep": "Договориться о звонке",
    "nextStepOwner": "COORDINATOR",
    "nextStepDate": "2026-11-03",
    "internalNote": "Уточнить удобное время при следующем контакте."
  }
}
```

`status`: `NEW`, `IN_REVIEW`, `CONTINUE`, `PAUSED`, `DECLINED`. Это результат знакомства, не статус документов или допуска. Сообщение обязательно (до 2000 символов), следующий шаг необязателен (до 500), внутренняя заметка — до 4000. Пробелы по краям текстов убираются. Следующий шаг требует `nextStepOwner` (`VOLUNTEER` или `COORDINATOR`); дата `YYYY-MM-DD` необязательна. Если шага нет, ответственный и дата должны быть `null`. Все изменения сохраняются в истории; черновиков и отложенной публикации пока нет.

Новая ревизия получает следующий номер, автора из сессии и время БД. Точный повтор нормализованного текущего состояния возвращает его без новой ревизии. Другая устаревшая версия даёт `409`; состояние и история не меняются. История доступна только для чтения.

`GET /onboarding/me` возвращает только `status`, `message`, `nextStep`, `nextStepOwner`, `nextStepDate`, `updatedAt`. Профиль выбирается по сессии, ID клиента не используется. Внутренние заметки, авторы, версия и история не входят в ответ. При отсутствии решения возвращается `NEW` с пустыми текстами. Изменения появляются после обновления блока или страницы; автоматические рассылки ещё не подключены.

## Оформление и допуски

Все маршруты `/coordination/...` ниже требуют координатора с завершённым входом по коду; изменения дополнительно требуют CSRF.

| Метод | Путь                                                | Результат                                                                 |
| ----- | --------------------------------------------------- | ------------------------------------------------------------------------- |
| GET   | `/coordination/volunteer-roles`                     | `200`, массив `{id, name, description, version}`                          |
| POST  | `/coordination/volunteer-roles`                     | `201`, новый вид помощи                                                   |
| PUT   | `/coordination/volunteer-roles/{roleId}`            | `200`, обновлённые название и описание                                    |
| GET   | `/coordination/volunteers/{id}/paperwork`           | `200`, состояние оформления и история                                     |
| PUT   | `/coordination/volunteers/{id}/paperwork`           | `200`, сохранённое решение и история                                      |
| GET   | `/coordination/volunteers/{id}/admissions/{roleId}` | `200`, допуск к выбранному виду помощи и история                          |
| PUT   | `/coordination/volunteers/{id}/admissions/{roleId}` | `200`, сохранённое решение и история                                      |
| GET   | `/onboarding/me/clearance`                          | Волонтёр: `200`, собственные оформление и допуски; `404`, если нет анкеты |

Справочник видов помощи относится к предметной области, а не к ролям `VOLUNTEER`/`COORDINATOR` в `identity`. При создании передаются `{name, description}`; при изменении — `{version, fields: {name, description}}`. Название обязательно, до 100 символов, описание до 1000. Крайние пробелы убираются, внутренние пробельные последовательности названия превращаются в один пробел. Названия уникальны без учёта регистра (`409` при совпадении). Версия начинается с `0`. Повтор одинаковых метаданных не меняет версию; отличающаяся устаревшая запись даёт `409`. Переименование сохраняет ID и ранее принятые решения по допускам. Изменения справочника записываются в аудит; публичного API удаления или истории справочника пока нет.

Ответы оформления и допуска имеют вид `{current, history}`. Снимок: `{fields, version, updatedAt, actorId, actorEmail}`, где `fields` — `{status, message, internalNote}`. История содержит последние 50 ревизий от новых к старым; полная история остаётся в БД. Email автора подставляется из текущего аккаунта, ID и время записываются вместе с решением. Исходное состояние имеет версию `0`, пустые тексты, `null` у автора и времени, пустую историю. Чтение не создаёт записи.

Сохранение оформления:

```json
{
  "version": 0,
  "fields": {
    "status": "CONFIRMED",
    "message": "Оформление проверено координатором.",
    "internalNote": "Внутреннее пояснение о проверке."
  }
}
```

Состояния оформления: `NOT_CONFIRMED`, `CONFIRMED`, `NEEDS_UPDATE`. Допуск сохраняется тем же форматом с состояниями `NOT_GRANTED`, `GRANTED`, `SUSPENDED`, `REVOKED`. Пояснение `message` обязательно и ограничено 2000 символами; внутренняя заметка — 4000. Крайние пробелы убираются. Пропущенная заметка становится пустой: это полная замена, не PATCH. Разрешено повторное подтверждение после приостановки/отзыва с новой записью истории. Порядок знакомства, оформления и выдачи допуска не навязан.

У оформления и каждой пары «волонтёр + вид помощи» своя версия. Одновременные отличающиеся изменения одной версии дают один успех и один `409`; состояние и история сохраняются одной транзакцией. Повтор текущих нормализованных полей не создаёт ревизию. Неизвестный профиль или вид помощи — `404`.

Собственный ответ содержит `paperwork: {status, message, updatedAt}` и `admissions: [{role: {id, name, description, version}, status, message, updatedAt}]`. В допусках возвращаются только виды помощи, для которых уже сохранено решение, включая приостановленные и отозванные. Внутренних заметок, авторов и истории в этом ответе нет. Профиль определяется сессией; изменения видны при следующем чтении без повторного входа. Подтверждение оформления не выдаёт допуск, допуск не меняет оформление или роли аккаунта, рассмотрение анкеты остаётся независимым.

## Ошибки

`400` — невалидные поля, параметры или JSON; `401` — неверные данные входа/код либо отсутствие или отзыв сессии; `403` — недостаточная роль, закрытый маршрут или неверный CSRF; `404` — объект не найден, чужое прохождение или снятая публикация; `409` — занятый email, конфликт версии или недопустимый учебный шаг; `429` — лимит запросов/писем; `503` — ошибка доставки кода.

Ошибки контроллеров возвращаются как ProblemDetail с `status` и `detail`. Валидация полей дополнительно возвращает `errors` — словарь сообщений без переданных значений. Ответ `401` от security-фильтра может иметь пустое тело, поэтому клиент выбирает запасное сообщение по статусу. Данные аккаунта никогда не включают хеш пароля.

## Обучение

Сотруднику нужна роль `COORDINATOR` и завершённый вход по коду. Волонтёру нужна собственная сохранённая анкета. Все изменения требуют CSRF.

| Метод | Путь                                           | Результат                                                           |
| ----- | ---------------------------------------------- | ------------------------------------------------------------------- |
| GET   | `/coordination/learning/courses`               | Список `{id, title, revision, publishedVersion, publishedRevision}` |
| POST  | `/coordination/learning/courses`               | `201`, новый пустой черновик, тело не нужно                         |
| GET   | `/coordination/learning/courses/{id}`          | Черновик `CourseDraft`                                              |
| PUT   | `/coordination/learning/courses/{id}`          | Полная замена `{revision, content}`; `409` при устаревшей правке    |
| POST  | `/coordination/learning/courses/{id}/publish`  | `{revision}` → `CourseDraft` с номером публикации                   |
| POST  | `/coordination/learning/courses/{id}/withdraw` | `{publishedVersion}` → `CourseDraft` без текущей публикации         |
| GET   | `/coordination/volunteers/{id}/learning`       | Прогресс всех версий, включая снятые с публикации                   |
| GET   | `/learning/courses`                            | Доступные опубликованные маршруты и собственные прохождения         |
| POST  | `/learning/courses/{id}/start`                 | `{version}` → собственное прохождение этой текущей версии           |
| GET   | `/learning/enrollments/{id}`                   | Собственное прохождение с уроками и последней обратной связью       |
| POST  | `/learning/enrollments/{id}/answers`           | Ответ на текущий незавершённый шаг → обновлённое прохождение        |

`CourseDraft`: `{id, revision, content, publishedVersion, publishedRevision}`. Ревизия черновика начинается с `0`, публикации с `1`; номера публикаций не переиспользуются после снятия. `publishedRevision` показывает ревизию, из которой создана текущая публикация; обе ссылки `null`, если маршрут не опубликован. Идентичное нормализованное сохранение не создаёт ревизию. Повтор публикации той же ревизии не создаёт новую версию. При снятии уже снятого маршрута возвращается текущее состояние; другой текущий номер публикации даёт `409`.

`content`: `{title, description, audience, demo, lessons}`. Аудитория `ALL_VOLUNTEERS` или `CONFIRMED_PAPERWORK`, `demo` — явная пометка примера. Название до 150 символов, описание до 2000. До 40 уроков:

```json
{
  "id": "ec2cd0e1-2530-424a-92a8-4292bcc9ed01",
  "title": "Где посмотреть следующий шаг?",
  "body": "Демонстрационный вопрос о кабинете.",
  "type": "SINGLE_CHOICE",
  "options": [
    { "id": "00000000-0000-4000-8000-000000000001", "text": "В моей анкете" },
    {
      "id": "00000000-0000-4000-8000-000000000002",
      "text": "В форме регистрации"
    }
  ],
  "correctOptionId": "00000000-0000-4000-8000-000000000001",
  "explanation": "Следующий шаг координатора отображается рядом с вашей анкетой."
}
```

Название урока до 150 символов, материал до 10000, объяснение до 2000, вариант до 500; максимум 8 вариантов. UUID уроков внутри маршрута и вариантов внутри урока должны различаться. Текст обрезается по краям. Неполный черновик допустим; публикация требует название маршрута, хотя бы один урок, название и материал каждого урока. `READ` не содержит вариантов и ключа. `SINGLE_CHOICE` требует минимум два непустых варианта, ключ одного из них и объяснение. `ORDERING` требует минимум два варианта и объяснение; правильный порядок задаётся порядком `options`, `correctOptionId` равен `null`. В ученической проекции варианты сортируются по UUID, ключ не возвращается.

Каталог волонтёра: `[{id, title, description, version, demo, totalLessons, enrollments}]`. Элемент `enrollments` и `summary` отдельного прохождения имеют вид `{id, courseId, title, version, completedLessons, totalLessons, startedAt, completedAt}`. Время — ISO 8601; `completedAt` до завершения равен `null`. Начало идемпотентно по профилю, маршруту и версии; устаревшая текущая версия даёт `409`.

Прохождение: `{summary, description, demo, lessons}`. Урок: `{id, title, body, type, options, available, completed, feedback}`. Неразблокированные уроки возвращают пустые `body` и `options`. `feedback` до ответа равен `null`, после него — `{correct, explanation, optionId, order}` с последней собственной попыткой. Ошибочный учебный ответ — успешный HTTP `200` с `correct: false`, не ошибка запроса. Его можно исправить.

Запись ответа:

```json
{
  "requestId": "513526f6-cd59-4d21-b5af-57eadcb39ac6",
  "lessonId": "ec2cd0e1-2530-424a-92a8-4292bcc9ed01",
  "optionId": "00000000-0000-4000-8000-000000000001",
  "order": []
}
```

Для чтения `optionId: null`, `order: []`; для выбора передаётся один существующий `optionId`; для порядка — `optionId: null` и перестановка всех UUID вариантов без повторений. Чужой вариант, неполный/дублирующий порядок и несоответствие типу — `400`. Пропуск шага или новый ответ на завершённый урок — `409`. Клиент не передаёт результат проверки, владельца или число пройденных уроков.

Повтор того же `requestId` и содержимого в рамках прохождения возвращает актуальное прохождение без новой попытки, даже если уже пройдены следующие шаги. Тот же ключ с другим ответом или уроком даёт `409`. После потери ответа сервера клиент повторяет запрос с прежним ключом.

Для чтения, старта и ответа, включая идемпотентный повтор, сервер проверяет текущее оформление. Учитываются обе аудитории: текущей публикации и закреплённой версии. Отсутствие подтверждения даёт `403`; такие материалы исключаются из каталога. Чужое прохождение, отсутствующая анкета или снятая публикация — `404`. Снятие закрывает все версии для волонтёров, сохраняя историю. Завершение курса не изменяет оформление, допуски, рассмотрение или роли аккаунта.

## Возможности помощи

Этап 5А добавляет описания возможностей. Конкретные занятия с датами, отклики, вместимость и подтверждение участия ещё не реализованы. Поля `schedule` и `location` описывают ожидаемый формат словами и не создают запись в расписании.

Координатору нужен вход с кодом; каждый POST/PUT требует CSRF. `OpportunityDraft` содержит `{id, revision, content, publishedVersion, publishedRevision}`. Список координатора содержит `{id, title, revision, publishedVersion, publishedRevision}`.

| Метод | Путь                                        | Результат                                                                      |
| ----- | ------------------------------------------- | ------------------------------------------------------------------------------ |
| GET   | `/coordination/opportunities`               | Список черновиков и состояния публикации                                       |
| POST  | `/coordination/opportunities`               | Без тела → `201`, новый черновик                                               |
| GET   | `/coordination/opportunities/{id}`          | `OpportunityDraft`; неизвестный ID — `404`                                     |
| PUT   | `/coordination/opportunities/{id}`          | `{revision, content}` → сохранённый черновик                                   |
| POST  | `/coordination/opportunities/{id}/publish`  | `{revision}` → черновик с новой текущей публикацией                            |
| POST  | `/coordination/opportunities/{id}/withdraw` | `{publishedVersion}` → черновик без текущей публикации                         |
| GET   | `/opportunities`                            | Страница доступных опубликованных карточек                                     |
| GET   | `/opportunities/filters`                    | `{roles: [{id, name, description, version}]}` — виды помощи текущих публикаций |
| GET   | `/opportunities/{id}`                       | Подробная опубликованная карточка; скрытая или неизвестная — `404`             |

Содержимое черновика:

```json
{
  "title": "Демо: подготовка материалов",
  "summary": "Вымышленная возможность для проверки каталога.",
  "description": "Демонстрационное описание помощи, не предложение реального участия.",
  "roleId": "00000000-0000-4000-8000-000000000001",
  "regularity": "FLEXIBLE",
  "location": "Демонстрационная площадка",
  "schedule": "Время согласуется с координатором",
  "requirements": "Условия будут уточнены фондом.",
  "training": "Подготовка будет уточнена фондом.",
  "demo": true
}
```

`roleId` ссылается на существующий вид помощи; в неполном черновике допустим `null`. Неизвестный ненулевой ID отклоняется. `regularity`: `ONE_OFF`, `REGULAR`, `FLEXIBLE`. Название — до 150 символов, краткое описание — до 500, полное — до 6000, место и ритм/время — до 500 каждый, условия и подготовка — до 2000 каждый. Текст обрезается по краям, HTML не исполняется. Публикация требует непустых `title`, `summary`, `description`, `location`, `schedule` и выбранного существующего вида помощи. `requirements` и `training` необязательны.

Ревизия черновика начинается с `0`. Нормализованный точный повтор сохранения не меняет ревизию; другая устаревшая правка — `409`. Правки не меняют уже опубликованную карточку до следующей публикации. Опубликованные снимки неизменяемы, номера начинаются с `1` и не переиспользуются. Повтор публикации текущей ревизии идемпотентен. При снятии проверяется номер текущей публикации (`409` при несовпадении); повтор снятия уже скрытой карточки ничего не меняет. Действия и авторы записываются в аудит одной транзакцией. Исходная база не содержит карточек фонда.

Каталог принимает `q` (до 120 символов, буквальная подстрока названия или краткого описания без учёта регистра), необязательные `regularity` и `roleId`, `page` (0–100000), `size` (1–100, по умолчанию 20). `%`, `_` и обратная косая черта не становятся шаблонами поиска. Сортировка: время текущей публикации по убыванию, затем ID. Ответ `{items, total, page, size}`. Фильтры видов помощи строятся по всем текущим публикациям, независимо от выбранной страницы и поискового запроса.

Краткая карточка: `{id, title, summary, regularity, location, schedule, role, demo, version, admissionStatus}`. `role` содержит текущие `{id, name, description, version}` из справочника; переименование не требует перепубликации. `admissionStatus` — собственный допуск к этому виду помощи (`NOT_GRANTED`, `GRANTED`, `SUSPENDED`, `REVOKED`), а не разрешение на конкретное занятие. Подробная карточка добавляет `description`, `requirements`, `training`, `publishedAt` (UTC, ISO 8601). Черновики, аудит и данные других волонтёров в эти ответы не входят.

Для всех трёх маршрутов волонтёра необходимы собственная анкета и актуальное `CONFIRMED` оформление. Нет анкеты — `404`; нет подтверждения или оно отозвано — `403`, включая прямое чтение карточки и фильтров. Каталог и допуски читаются согласованно в `REPEATABLE_READ`. Рабочее допущение этого этапа: оформленный волонтёр может просматривать карточки разных видов помощи, даже если ещё не имеет соответствующего допуска. Просмотр не создаёт отклик и не подтверждает участие. При отказе в доступе интерфейс очищает загруженные карточки.
