# Telegram-бот

Бот уведомляет о публичных изменениях рассмотрения анкеты, документов и допусков. Внутренние заметки не отправляются. Кабинет работает без Telegram; бот не выдаёт права и не заменяет координатора.

## Запуск

1. Создать бота через @BotFather командой /newbot.
2. В локальном `.env` заполнить `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` (без @), `TELEGRAM_SITE_URL` (публичный HTTPS-адрес сайта), установить `TELEGRAM_ENABLED=true`.
3. Пересоздать backend: `docker compose up -d --build backend web`. Токен не коммитить, не помещать в переменные VITE и не отправлять в чат.
4. В личном кабинете нажать «Подключить Telegram», открыть ссылку и нажать «Запустить». Затем «Проверить подключение».

Используется getUpdates, публичный webhook не нужен. На этом боте не должен быть установлен webhook; если он ранее использовался, удалите его перед запуском polling. Команды: /start, /help, /status, /settings, /stop. Работает только личный чат. /stop или кнопка отключения отменяет ожидающие уведомления.

## API и интеграция

GET `/api/v1/notifications/telegram`: available, linked. POST `/link`: url, expiresInSeconds. POST `/unlink`: обновлённый статус. Все пути относительно `/api/v1/notifications/telegram`. Требуются сессия волонтёра и CSRF для POST. Ссылка одноразовая, срок 10 минут, в БД хранится SHA-256, новая ссылка отменяет старую. Один Telegram соответствует одному аккаунту.

Очередь записывается в одной транзакции с решением координатора. Сеть вызывается фоновым обработчиком после фиксации. Повторы ограничены восемью попытками, учитывается retry_after; 403 отключает связь. Курсор входящих обновлений сохраняется в БД, обработчики сериализованы блокировкой строки. Доставка at-least-once: при сбое между ответом Telegram и фиксацией БД возможен повтор сообщения. История очереди удаляется через 30 дней. FAILED — терминальная ошибка; отслеживайте количество таких записей при эксплуатации. Сообщения и токены не пишутся в лог ошибок.

Для новых бизнес-сценариев вызывайте публичный `VolunteerNotifications.enqueue(accountId, eventKey, message)` в транзакции основного действия, с уникальным стабильным ключом события. Уведомление «принят в команду / обучение открыто» нужно подключить к отдельному серверному решению о приёме: бот сейчас не приравнивает документы или допуск к этому решению. События занятий и напоминания подключаются после реализации записи на занятия. Старые события после привязки не рассылаются.

Проверка вручную: привязать → изменить публичный следующий шаг координатором → получить уведомление → изменить только внутреннюю заметку (сообщения нет) → /stop → изменить решение (сообщения нет). Повторное использование ссылки и чужой сессии должно отклоняться. Не запускайте smoke-тесты на чужих аккаунтах.
